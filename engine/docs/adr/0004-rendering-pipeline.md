# ADR-0004: Canvas → DisplayList → Scene → сменный растеризатор; CPU первым

- Статус: принято
- Дата: 2026-11-17

## Контекст

Нужно отделить «что нарисовать» от «как получить пиксели», чтобы бэкенд отрисовки можно было менять
(CPU сейчас, GPU потом), а framework при этом не переписывать.

## Решение

1. Framework рисует только через интерфейс `gfx.Canvas`. `gfx.Recorder` записывает команды в
   `gfx.DisplayList` — неизменяемый список команд (аналог `Picture` во Flutter).
2. Из слоёв (`Offset`, `Transform`, `Clip*`, `Opacity`, `Picture`) собирается `layer.Scene` и уходит
   в raster-раннер.
3. `raster.Rasterizer` — интерфейс. Первая реализация — `raster/soft` (CPU):
   - кривые Безье → полилинии (адаптивное деление);
   - покрытие пикселей с антиалиасингом: аккумуляция знаковых площадей (как font-rs и `x/image/vector`);
   - правила заливки non-zero и even-odd;
   - смешивание SrcOver в premultiplied RGBA; клипы (сначала прямоугольные, потом по пути — через маску);
   - обводка (stroke) — отдельный этап: преобразуем в заливку с join-ами и cap-ами.
4. Формат `DisplayList`: **сначала** — срез типизированных команд (просто, удобно отлаживать);
   **потом**, когда бенчмарк покажет аллокации, — компактный буфер «op-код + []float32».
   Это осознанное учебное упражнение «сначала измерь, потом оптимизируй».
5. Смешивание цветов — в sRGB, как Skia/Flutter по умолчанию (чтобы цвета совпадали с ожиданиями
   дизайнеров). Линейное смешивание — отдельный ADR, если понадобится.

## Почему CPU первым

- Работает везде, включая headless и CI, без драйверов.
- Детерминированные golden-тесты.
- Самый учебный путь: видно каждый пиксель, нет «магии» видеокарты.
- Граница `DisplayList` гарантирует, что GPU-бэкенд потом встанет без переписывания framework.

## Альтернативы

- Skia через cgo: быстро и качественно, но огромная C++-зависимость, cgo везде и ноль учебной ценности.
- Сразу GPU (WebGPU, D3D11, GL): быстрее на больших экранах, но рендеринг путей на GPU — отдельная
  исследовательская задача, и без эталона на CPU его не с чем сравнивать.

## Последствия

- На больших экранах CPU медленный — смягчаем repaint boundaries и перерисовкой только грязных регионов.
- GPU-бэкенд (M11) проверяется теми же golden-тестами, что и soft (в допуске).
