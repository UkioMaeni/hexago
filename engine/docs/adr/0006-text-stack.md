# ADR-0006: Текст — go-text для шейпинга, своя вёрстка абзаца

- Статус: принято
- Дата: 2026-11-17

## Контекст

Текст — самая недооценённая часть UI-движка. Цепочка: шрифты → шейпинг (выбор глифов, лигатуры,
кернинг, сложные письменности) → переносы → bidi → строки → растеризация глифов → кеш.
Шейпинг уровня HarfBuzz — это годы работы экспертов.

## Решение

- **Берём готовое:** `github.com/go-text/typesetting` — чистый Go (без cgo): парсинг шрифтов,
  шейпинг (порт HarfBuzz), сегментация Unicode. Его же используют Gio и Fyne.
- **Пишем сами:** вёрстку абзаца (`Paragraph`): разбиение на прогоны по стилю/скрипту/направлению,
  фолбэк шрифтов, переносы, выравнивание, многоточие, метрики строк, hit-test (точка → позиция в тексте),
  прямоугольники выделения и каретки.
- **Глифы растеризуем своим** `raster/soft` (контур глифа — это путь) и кешируем по ключу
  (шрифт, глиф, размер, субпиксельный сдвиг по X с шагом 1/4).
- **Шрифты:** сначала один встроенный шрифт под OFL-лицензией (через `embed`), системные шрифты — позже.
- `gfx` не импортирует `text`: `GlyphRun` ссылается на шрифт через маленький интерфейс в `gfx`,
  который реализует `text`. Растеризатор получает контуры глифов, не завися от текстового стека.

## Альтернативы

- `golang.org/x/image/font`: нет шейпинга — не будет арабского, деванагари, лигатур.
- FreeType + HarfBuzz через cgo: эталонное качество, но ломает «без cgo» и кросс-компиляцию.
- Свой HarfBuzz: интересно, но это отдельный проект на годы.

## Последствия

- Одна внешняя зависимость в ядре — сознательная, зафиксирована в `internal/archtest`.
- Отладка шейпинга — в чужом коде; наша зона ответственности начинается с результата шейпинга.
