# ADR-0008: Слои пакетов, проверка тестом

- Статус: отложено [ADR-0012](0012-mobile-first-cli-and-layout.md) — тест вернём, когда появятся слои движка
- Дата: 2026-11-17

## Контекст

В большом проекте архитектура разрушается не решениями, а мелкими «удобными» импортами:
виджету понадобился размер окна — импортнул `platform/win32`, и тестируемость ушла.

## Решение

- Для каждого пакета задан allow-list: какие пакеты модуля и какие внешние модули ему можно импортировать.
- Таблица `rules` в `internal/archtest/layers_test.go` — единственный источник правды; копия для
  чтения — в `docs/ARCHITECTURE.md` §12.
- Пакет без правила — красный тест: новый пакет обязан занять место в архитектуре осознанно.
- Импорт `"C"` (cgo) разрешён только в `platform/...`.
- Тест читает импорты через `go/parser` (stdlib), включая файлы под любыми build-тегами,
  поэтому ловит нарушения и в `_windows.go`, и в `_js.go` файлах.

## Альтернативы

- Линтеры (depguard, go-arch-lint): мощнее, но внешняя зависимость и отдельный конфиг.
  Свой тест на 150 строк понятен целиком и сам по себе учебный.

## Последствия

- `go test ./...` ловит нарушения архитектуры так же, как сломанную логику.
- Менять правило можно, но осознанно — вместе с ARCHITECTURE.md, а для крупных сдвигов — с ADR.
