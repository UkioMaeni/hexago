# ADR-0010: float32 и логические пиксели

- Статус: заменено [ADR-0013](0013-flutter-widgets-course.md) — геометрия во float64
- Дата: 2026-11-17

## Контекст

Нужен один числовой тип для геометрии и одна система координат для framework. На Windows часто
дробный масштаб экрана: 125 %, 150 %, 175 %.

## Решение

- Вся геометрия — `float32` (`geom.Point{X, Y float32}` и т. д.).
- Framework живёт в **логических пикселях**. Физические пиксели есть только в `platform` и `raster`.
- Масштаб (device pixel ratio) применяется один раз — трансформацией в корне render-дерева
  (`RenderView`), как во Flutter.
- Привязка к пиксельной сетке (pixel snapping) для чётких тонких линий — при отрисовке, а не в лэйауте.

## Альтернативы

- `float64` (как `double` в Dart; пакет `math` работает с float64): вдвое больше памяти в DisplayList,
  GPU всё равно хочет float32.
- `int` в пикселях (как лэйаут в Gio): проблемы округления при дробном масштабе.

## Последствия

- Нужны мелкие помощники в `geom` поверх `math` (`float32` ↔ `float64`).
- Точности float32 (~7 значащих цифр) хватает для UI-координат; в очень глубоких цепочках трансформаций
  следим за накоплением ошибки (тесты).
