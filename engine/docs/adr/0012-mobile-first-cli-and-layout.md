# ADR-0012: Мобильная платформа первой; консольная программа hexago; весь код в engine/

- Статус: принято. Пункты 4–5 (как устроены `hexago create` и Android-хост) уточнялись при реализации.
  Заменяет порядок платформ из ADR-0007 (п. 6), откладывает тест слоёв из ADR-0008.
- Дата: 2026-11-17

## Контекст

- Автор хочет начать с мобильной части, а не с десктопа.
- Первый инструмент — консольная команда, которая создаёт проект, как `flutter create`.
- Скелет из 22 пустых пакетов «на вырост» мешал видеть проект: структура должна быть аккуратной сразу.

## Решение

1. **Порядок платформ:** Android → iOS (нужен Mac с Xcode) → Windows и Web → Linux и macOS.
2. **Раскладка:** весь код — в папке `engine/` (Go-модуль `hexago`). В корне репозитория — только `engine/`
   и служебные файлы. Пакет создаётся, когда начинается его этап, — пустых заглушек нет.
   Документы лежат в `engine/docs/`.
3. **Консольная программа отдельно от утилит**, как во Flutter (`bin/flutter` → `flutter_tools`):
   `engine/main.go` только передаёт аргументы в пакет `tools`, а каждая команда там — значение типа `Command`.
   `go install .` из `engine/` даёт `hexago.exe`.
4. **`hexago create <папка>`** создаёт Go-часть (`main.go`, `go.mod`) и `android/` — Gradle-проект на Kotlin DSL.
   Шаблон встроен в бинарник через `embed` (`engine/tools/templates/app`).
5. **Android-хост:**
   - своя Activity, а не `NativeActivity`: ввод текста (`InputConnection`), доступность и жизненный цикл —
     под нашим контролем, как во Flutter; `NativeActivity` — тупик для IME;
   - Java, а не Kotlin: Activity — тонкая прослойка, Kotlin-плагин был бы лишней зависимостью;
   - сейчас `MainActivity` — заглушка; потом она наследует `HexagoActivity` (SurfaceView + JNI в Go-библиотеку
     `libmain.so`, собранную `go build -buildmode=c-shared` с clang из NDK);
   - версии: AGP 9.0.1, Gradle 9.8.2, compileSdk и targetSdk 36, minSdk 26 — константы в `engine/tools/create.go`;
   - `gradlew` и `gradle-wrapper.jar` пока не генерируются (jar — бинарный файл): Android Studio берёт Gradle
     по `gradle-wrapper.properties`. Сборка из командной строки — задача будущей `hexago build`.
6. **Тест слоёв (ADR-0008) отложен:** пока пакетов один-два, защищать нечего. Его код лежит в
   `C:\dev\projects\gexago_old\internal\archtest`; вернём, когда появятся слои движка.

## Альтернативы

- Десктоп первым (прежний план): самый быстрый цикл разработки, но автору важнее мобильная часть.
- Сборка APK без Gradle, напрямую через aapt2, javac и d8 (так делает gogio из Gio): быстрее и меньше
  зависимостей, но проект нельзя открыть в Android Studio, и это не «как во Flutter».

## Последствия

- Цикл «правка → результат» на телефоне медленнее (сборка + установка), поэтому headless- и golden-тесты
  на компьютере становятся ещё важнее.
- iOS на Windows не собрать — для этапа iOS понадобится Mac.
- cgo и NDK понадобятся уже на этапе M2, раньше, чем планировалось.
