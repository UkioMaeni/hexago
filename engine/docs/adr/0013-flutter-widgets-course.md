# ADR-0013: Практичный курс на виджеты Flutter

- Статус: принято. Заменяет ADR-0010 (float32), уточняет ADR-0004 (растеризация), ADR-0003 (ключи).
- Дата: 2026-11-17

## Контекст

Цель сменилась: нужны рабочие виджеты Flutter на нашем движке с отрисовкой на Android — как можно
раньше. Учебная цель «написать каждую строку руками» больше не главная.

## Решение

1. **Приоритет — рабочий результат.** Каждый этап проверяется (тесты, PNG-эталоны, скриншот эмулятора)
   и фиксируется коммитом.
2. **API виджетов — как во Flutter**, с поправкой на Go: struct-литералы вместо именованных параметров,
   `new(200.0)` для необязательных чисел, имена полей как во Flutter (`Color`, `Padding`, `Children`,
   `MainAxisAlignment`...).
3. **Числа — `float64`** во всей геометрии (заменяет ADR-0010). Так уже написаны первые виджеты
   (`Width *float64`), так устроен `math` и `double` в Dart. В `float32` переводим только на границе
   с растеризатором.
4. **Зависимости:**
   - `golang.org/x/image/vector` — растеризация путей со сглаживанием (аккумуляция покрытия), той же
     конструкции, что планировалась для своего растеризатора, но уже проверенная.
   - `github.com/go-text/typesetting` — шрифты, шейпинг, переносы (как и решено в ADR-0006).
5. **Конвейер кадра — сначала простой:** перестроить «грязные» элементы, затем полный лэйаут и полная
   отрисовка дерева в один программный буфер. Relayout/repaint boundaries — позже, как оптимизация,
   когда профилирование покажет необходимость.
6. **Ключи** — обёрткой `widgets.Keyed(key, child)`, а не полем в базе: литералы виджетов остаются короткими.
7. **Пакеты:** `ui/geom` (геометрия) → `ui/gfx` (цвет, холст, растеризация) → `ui/text` → `ui/rendering`
   (render-дерево) → `ui/widgets` (виджеты, элементы, состояние) → `ui/material` (дизайн-система) →
   `ui/app` (запуск). `ui/hexagotest` — проверка виджетов без устройства, с PNG-эталонами.
8. **Команды `hexago`:** `create`, `run`, `version` и `test` — проверка окружения, как `flutter doctor`.
   Имя `test` выбрал автор.

## Последствия

- Прогресс быстрее; документы и комментарии остаются подробными, чтобы код можно было изучать.
- Простой конвейер может стать узким местом на сложных экранах — тогда займёмся инкрементальной отрисовкой.
