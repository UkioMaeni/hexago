# ADR-0014: Устройства и эмуляторы — hexago devices, hexago emulators, run -d, выбор в VS Code

- Статус: принято
- Дата: 2026-11-18

## Контекст

- Автор привык к Flutter: справа внизу в VS Code видно, на каком устройстве запустится приложение,
  а по щелчку — список телефонов и эмуляторов, выключенный эмулятор можно запустить оттуда же.
- До этого `hexago run` брал единственное подключённое устройство или серийный номер из `-d`;
  выключенный эмулятор приходилось запускать из Android Studio.
- Расширение VS Code проверяло `go.mod` один раз, при старте. Если открыть пустую папку и выполнить
  в ней `hexago create .`, ни кнопки запуска, ни выбора устройства не появлялось.

## Решение

1. **`hexago devices [--json] [--watch]`** — подключённые телефоны и запущенные эмуляторы (как `flutter devices`).
   Для каждого: серийный номер, имя для людей (модель телефона или имя эмулятора), версия Android, ABI, состояние.
   Состояния — как у adb, плюс `booting`: adb уже видит устройство, но Android ещё не загрузился
   (`sys.boot_completed` ≠ 1), ставить приложение рано.
   `--watch` печатает список заново при каждом изменении (опрос adb раз в 2 секунды; свойства уже
   загруженного устройства не переспрашиваются) и завершается, когда закрывается stdin, — так процесс не
   переживает редактор, который его запустил.
2. **`hexago emulators [--json] [--launch имя]`** — эмуляторы из Android Studio (как `flutter emulators`).
   `--launch` запускает эмулятор отдельным процессом и не ждёт его: окно эмулятора живёт само по себе.
3. **`hexago run -d`** принимает серийный номер, имя устройства или имя эмулятора (без учёта регистра).
   Выключенный эмулятор `run` запускает сам и ждёт загрузки (до 3 минут); загружающееся устройство тоже ждёт.
   Flutter так не умеет — у него эмулятор запускают отдельной командой, — но это убирает лишний шаг.
4. **Расширение VS Code:**
   - включается после старта редактора (`onStartupFinished`) и следит за `go.mod`: проект Hexago замечается,
     как только появляется, в том числе после `hexago create .` в уже открытой папке;
   - справа в строке состояния — устройство, на котором запустится приложение; список ведёт
     `hexago devices --json --watch`; выбор запоминается для проекта (состояние рабочей области);
   - по щелчку — список устройств и выключенных эмуляторов («Запустить …»);
   - ▶ Hexago вызывает `hexago run android -d <устройство>`; если устройств нет — сначала предлагает выбрать
     или запустить эмулятор.

## Альтернативы

- `adb track-devices` вместо опроса: изменения приходят сразу, но вывод — сырой протокол adb
  (длина в hex + строки), а свойства устройства всё равно нужно спрашивать отдельно. Опрос раз в 2 секунды
  проще и для человека незаметен.
- Долгоживущий «демон» hexago с JSON-RPC, как `flutter daemon`: правильнее, когда команд для редактора станет
  много (горячий перезапуск, логи, отладка). Пока хватает отдельных команд с `--json`.
- Опрашивать устройства из TypeScript напрямую через adb: тогда логику пришлось бы писать дважды — в hexago
  и в расширении — и её нельзя было бы проверить тестами Go.

## Последствия

- Расширение запускает фоновый процесс hexago на время работы с проектом Hexago — он раз в 2 секунды
  вызывает `adb devices`.
- В недоверенной папке (Restricted Mode VS Code) расширения не работают — кнопки появятся, когда папке доверятся.
- Имя эмулятора берётся из свойств `ro.boot.qemu.avd_name` / `ro.kernel.qemu.avd_name`, на старых образах —
  из консоли эмулятора (`adb emu avd name`).
