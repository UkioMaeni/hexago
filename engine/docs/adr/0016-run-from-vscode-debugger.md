# ADR-0016: Запуск из VS Code через Run → Start Debugging; точки останова — позже

- Статус: принято
- Дата: 2026-11-18

## Контекст

- Во Flutter приложение запускают через F5 (Run → Start Debugging): лог — в Debug Console,
  на панели отладки ■ «Стоп» и ⟳ «Перезапуск». Автор ждёт того же.
- Настоящая отладка Go (точки останова, переменные) делается через Delve. Но на Android Go-код — это
  `libhexago.so` внутри Java-процесса, а Delve не умеет отлаживать Go, собранный с `-buildmode=c-shared`
  и загруженный в чужой процесс: такие обсуждения тянутся с 2017 года без решения.

## Решение

1. Расширение регистрирует отладчик `hexago`. Это тонкий адаптер протокола DAP прямо в расширении,
   без внешних библиотек: он запускает `hexago run android -d <устройство>`, передаёт вывод в Debug Console,
   по ■ завершает `hexago run` вместе с `adb logcat` (в Windows — всё дерево процессов). Перезапуск VS Code
   делает сам: останавливает и запускает заново. Точек останова адаптер не поддерживает.
2. Настройка в `launch.json`: `{"type": "hexago", "request": "launch"}`. Необязательное `device` —
   серийный номер, имя устройства или эмулятора; без него — устройство из строки состояния.
   F5 без `launch.json` работает так же.
3. `hexago create` кладёт в проект `.vscode/launch.json` с этой настройкой, чтобы F5 сразу запускал Hexago,
   а не спрашивал, каким отладчиком. Уже существующий `launch.json` не перезаписывается.
4. Кнопка ▶ Hexago в строке состояния запускает ту же настройку, что и F5.
5. Попутно: шаблон встраивается как `all:templates` — без `all:` `go:embed` молча пропускал файлы
   с точкой в начале имени, и в проекты не попадал `android/.gitignore`.

## Альтернативы

- Delve на устройстве (`dlv attach` через `run-as`, проброс порта, удалённая отладка из расширения Go):
  упирается в то, что Delve не видит Go внутри c-shared библиотеки.
- Запуск как задача VS Code (было до этого): лог в терминале, но F5 не работает, и нет панели отладки.

## Последствия

- Точки останова появятся, когда у Hexago будет запуск на компьютере (окно Windows с тем же
  программным рендером): там приложение — обычная программа на Go, и Delve работает как есть.
- Проекты получают папку `.vscode/` — другим редакторам она не мешает.
