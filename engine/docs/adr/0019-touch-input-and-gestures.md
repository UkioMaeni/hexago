# ADR-0019: Касания и жесты — пакет ui/gestures, арена, кадры по запросу

- Статус: принято
- Дата: 2026-11-18

## Контекст

- До этого приложение только рисовалось: касаний не было, а `SetState` не приводил к новому кадру —
  кадр рисовался, только когда Android сам менял поверхность.
- Автор попросил полноценный `GestureDetector`, сырые касания (`Listener`) и виджет, сквозь который
  касания проходят (`IgnorePointer`).

## Решение

1. **Новый пакет `ui/gestures`** между `geom` и `rendering`: `geom → gestures → rendering → widgets → app`.
   В нём события касаний (`PointerEvent`: Down, Move, Up, Cancel; координаты в dp), распознаватели и арена.
   О боксах и виджетах он не знает.
2. **Арена жестов** — как во Flutter. Пока палец опускается, в арену входят все распознаватели под ним;
   после этого она закрывается, и одиночный участник сразу побеждает. Дальше распознаватель может объявить
   победу или отказаться. Когда палец отпущен, нерешённая арена достаётся первому участнику — самому глубокому
   детектору. Двойное нажатие придерживает арену первого нажатия.
3. **Распознаватели:** нажатие (`OnTapDown` через 100 мс или при победе, `OnTapUp`, `OnTap`, `OnTapCancel`),
   двойное нажатие, долгое нажатие (500 мс, с движением после начала), перетаскивание по вертикали,
   по горизонтали и свободное, масштаб с поворотом. Пороги — как у Flutter и Android (18 dp, 36 dp,
   100/300/500 мс). Начало перетаскивания — точка касания, а первый `Update` несёт весь путь до порога:
   элемент точно следует за пальцем. Скорость броска — методом наименьших квадратов за последние 100 мс.
4. **Часы — через интерфейс `Clock`.** Таймеры жестов в приложении срабатывают в потоке интерфейса, а в тестах
   используется `FakeClock`: жесты, включая долгое и двойное нажатие, проверяются без устройства.
5. **rendering:** hit-test запоминает для каждого бокса преобразование «экран → бокс» (сдвиги детей,
   `Transform`), поэтому `Local` верен и для последующих событий пальца. Новые боксы: `PointerListenerBox`
   (режимы `DeferToChild`, `Opaque`, `Translucent`), `IgnorePointerBox`, `AbsorbPointerBox`.
6. **widgets:** `Listener` (сырые касания), `IgnorePointer` (касания проходят сквозь поддерево к тому, что под
   ним), `AbsorbPointer` (касания поглощаются), `GestureDetector` — виджет с состоянием (ADR-0018):
   распознаватели создаются по заданным обработчикам и живут в его состоянии. `OnPan…` и `OnScale…` вместе
   запрещены, как во Flutter. Касание раздаёт `Binding.HandlePointer`: hit-test на Down, дальше события
   пальца — тем же боксам; ошибка в обработчике печатается и не роняет приложение.
7. **Android:** `HexagoActivity` передаёт касания в Go (`nativeOnPointer`, с промежуточными точками движения),
   Go просит кадр (`requestFrame` → `Choreographer`: несколько просьб до развёртки дают один кадр) и ставит
   задачи в поток интерфейса (`wakeUp` → `Handler`). Для этого Go вызывает статические методы Java из любого потока.
8. **`app.Post(f)`** — выполнить f в потоке интерфейса. Виджеты и `SetState` живут в нём; из других горутин
   (сеть, таймеры) состояние меняют только через `Post`.

## Альтернативы

- Распознавать жесты прямо в виджетах, без арены: просто, но вложенные детекторы и пара
  «нажатие + прокрутка» начинают конфликтовать — арена Flutter решает это проверенным способом.
- Опрашивать касания из Go вместо JNI-обратных вызовов: лишние задержки и потоки.

## Последствия

- Каждый кадр перерисовывает весь экран программным растеризатором; для простых экранов этого хватает,
  оптимизация (перерисовка только изменившегося) — отдельная задача.
- Свободное перетаскивание отслеживает один палец; несколько пальцев — это `OnScale…`.
